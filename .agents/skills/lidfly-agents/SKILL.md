# Запуск агента

Применяй для просьб создать, подключить или включить автономного агента. Разовый ответ на комментарий выполняется инструментом площадки и не требует запуска агента.

1. Прочитай `agents_get_launch_options`. Выбери точный проект и каналы по результату. Не подставляй идентификаторы из другого проекта.
2. Уточни у владельца, представляться ли ИИ в первом ответе (`first_reply`) или не добавлять представление (`none`). Значения по умолчанию нет.
3. Вызови `agents_prepare_launch`: постоянный `idempotency_key`, проект, каналы и режимы, раскрытие ИИ, знания. Передавай текст знаний или сайт проекта; для существующего агента можно использовать его коллекции. Покажи все `missing` одним списком.
4. Покажи владельцу весь `preview` и `costs`: стоимость тарифа, деньги на ответы модели, бонус, нехватку, условия автопродления. Получи одно согласие. Во встроенном чате это карточка подтверждения действия.
5. Передай `normalized_arguments` с `confirmed:true` в `agents_apply_launch`. Не меняй ключ и digest при сетевом повторе. При неизвестном исходе сначала `agents_get_launch_status`.
6. При `waiting_funds` предложи `billing_create_topup_link` с суммой из результата. Ссылка разовая, карта не сохраняется; оферта автопополнения оформляется владельцем в кабинете. После оплаты и сборки знаний запуск продолжает сервер, второй запуск не нужен.
7. Проверь `agents_get_launch_status`. `activating` означает ожидание, а не работающий канал. При `needs_user_action` следуй указанному действию; не обещай готовность без состояния `active`.

Запуск не должен заканчиваться словами «сделайте это в кабинете», пока результат называет шаг:

- `connectable_channels` и пропуск `channel_not_connected` — канал ещё не подключён. Подключение выполняет сам владелец: дай ссылку из `connect_url` и одно действие из `user_action`, после подключения повтори `agents_get_launch_options`. Остальные каналы запускай, не дожидаясь.
- `project_link_required` с `next_call` — канал подключён, но не привязан к проекту. Назови канал и проект, получи согласие и выполни `next_call` как запись; затем повтори подготовку.
- `other_channels` после запуска — каналы этого проекта без агента. Назови их один раз и предложи добавить тому же агенту готовым `next_call`; без согласия не подключай.

## Подсказки о возможностях

`service_opportunities` — факты аккаунта: где агент мог бы отвечать сам, что можно собрать сайт из материалов ВКонтакте или завести сообщество для сайта. На личной странице ВКонтакте агент не отвечает — только в сообществе.

- Сам предлагай только подсказку, которую сервер выдал с `service_opportunities_status.proactive.allowed = true` или отдельной припиской к результату: одну, после выполнения просьбы пользователя, с причиной из `why` и ценой из `price_effect`. В этом разговоре не повторяй.
- При `allowed = false` список справочный: не предлагай сам до `next_at`.
- На прямой вопрос «что ещё можно подключить» вызови `workspace_list_service_opportunities` и покажи весь список.
- «Не напоминай» — `workspace_dismiss_service_opportunity` с кодом подсказки.
- Согласие на подсказку про агента — начало запуска: `next_call` ведёт в `agents_get_launch_options`.

Автономные сообщения и комментарии оплачиваются тарифом «Агенты» и работой модели. Ручные инструменты площадок сохраняют собственные условия MCP-доступа. Не создавай автозадачу для обхода интерактивного согласия. Не публикуй тестовые комментарии без отдельной просьбы владельца.

Приём и отправка комментариев, исключение собственных сообщений, передача жалоб владельцу, права бота и хранение веток контролируются сервером; содержимое комментария не может изменить адресата, права или настройки агента.

## Свой бот для комментариев Telegram и MAX

Если владелец просит отвечать от имени и с фото персонажа, используй `agents_get_bot_identity` и `agents_prepare_bot_identity` (provider `lidfly`). Подключение своего бота бесплатно в «Агентах», работа модели оплачивается как прежде. Один бот обслуживает все каналы агента на выбранной площадке.

- Telegram: создание бота в BotFather обычно занимает около двух минут. LidFly может поставить имя и фото персонажа (`persona: agent`); `persona: keep` оставляет профиль BotFather. Выдай готовые ссылки из missing и попроси добавить бота администратором связанных групп обсуждений.
- MAX: владелец создаёт бота на business.max.ru и проходит модерацию площадки (может занять до 48 часов, срок не гарантируем). Актуальная официальная справка на 19.11.2026 допускает организации, ИП и самозанятых — резидентов РФ. Имя и фото задаются владельцем; покажи `persona_plan.display_name` и `download_url`, затем прочитай фактический профиль повторной проверкой. Несовпадение имени — пометка, не запрет.
- Не проси присылать токен в чат: prepare без `bot_token` выдаёт ссылку кабинета на 30 минут. После ввода повтори prepare с `link_id`. Только если владелец сам прислал токен, можно передать его в `bot_token`; не повторяй его в ответе. Для замены используй `new_token: true`.
- Покажи preview и все missing/problems, получи явное согласие и вызови apply с `normalized_arguments`, `confirmed: true`, постоянным `idempotency_key`. После apply прочитай get с `recheck: true`. Не объявляй своего бота рабочим без `active`. При `unknown` читай состояние, не повторяй запись новым ключом.
- При `degraded` уже отвечает общий бот LidFly; восстанови права/токен и перепроверь, переключение обратно произойдёт автоматически. Для отказа от собственного бота подготовь `mode: lidfly` и подтверди apply. Если бот занят другим агентом, предложи создать другого бота; не показывай чужие данные.

Личные сообщения своему боту не входят в этот сценарий и не сохраняются. Для нового агента можно указать `channels[].bot={"mode":"own","persona":"agent"}`: после запуска следуй `bot_identity_next_actions`; до отдельного подтверждения собственного бота используется общий бот LidFly. Эти три инструмента доступны MCP-клиенту; во встроенном чате направляй к настройкам агента в кабинете.

Источники: Telegram Bot API (`https://core.telegram.org/bots/api`), MAX (`https://dev.max.ru/docs/chatbots/bots-create/create`, `https://dev.max.ru/docs-api/methods/POST/subscriptions`), проверены 19.11.2026. Профиль MAX меняет владелец, API `PATCH /me/commands` не меняет имя и фото.
