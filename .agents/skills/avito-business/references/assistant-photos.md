# Фотографии ИИ помощника Авито

Используй для просьб загрузить картинки ИИ продавцу, описать их, выбрать объявления или разрешить/отключить отправку покупателям. UI и MCP работают с одной приватной библиотекой. Фото в ней не меняют изображения самого объявления.

## Найти помощника и инструменты

1. Вызови напрямую `search_tools({ provider:"lidfly", query:"фотографии помощника Авито" })` и получи актуальные схемы через `get_tool_schema`. Если поиск не нашёл нужное, ищи точное имя из таблицы с тем же provider. Эти `ermiy_*` не находятся в каталоге `avito`.
2. Определи точный `workspace_project_id` выбранного проекта. Если проект неизвестен, найди его штатными read-инструментами «Проектов»; не создавай проект и не угадывай ID. Схемы `ermiy_list_agents` и `ermiy_list_bindings` тоже ищи в `lidfly`. Через `call_tool` прочитай помощников этого проекта, затем подключения выбранного помощника; продолжай пагинацию по схеме. Выбери именно подключение Авито. Не подменяй `binding_id` идентификатором профиля, объявления или `connection_id`; при неоднозначности уточни выбор.
3. Передавай одну и ту же тройку `workspace_project_id`, `agent_id`, `binding_id` во все фотоинструменты. Прочитай библиотеку и квоты. Для привязки к объявлениям прочитай `view:"items"` и скопируй проверенные ID; `items_forbidden` означает отказ доступа, а не пустой профиль.

| Инструмент | Действие |
| --- | --- |
| `ermiy_list_avito_photos` | `call_tool`: библиотека и квоты (`view:"photos"`, `next_cursor → after`) либо объявления (`view:"items"`, `page`, `has_more`). |
| `ermiy_request_avito_photo_upload` | `call_write_tool`: создать загрузку или восстановить ту же незавершённую загрузку по ключу. |
| `ermiy_get_avito_photo` | `call_tool`: прочитать состояние, описание, область и актуальную `revision` по `media_id`. |
| `ermiy_update_avito_photo` | `call_write_tool`: описание, область, порядок и `draft`/`active`/`archived` с `expected_revision` и ключом операции. |

Если инструмента нет в актуальном каталоге или он недоступен, следуй конкретной причине отказа, предложи UI. Навык не даёт дополнительных прав. Не обходи отказ прямым вызовом API Авито или поиском провайдерских секретов.

## Передать файл

До создания загрузки проверь, что среда клиента может прочитать **байты** пользовательского файла и выполнить HTTPS PUT. Вложение в ИИ-чате само по себе не гарантирует такой доступ. Если этих возможностей нет, направь в LidFly: «ИИ помощник» → нужное подключение Авито → «Фотографии». Во встроенном чате этот MCP-сценарий не исполняется. Не проси сделать приватное фото публичным ради загрузки.

1. Проверь исходник: JPEG, PNG или WebP, не более 10 МиБ и 40 Мп. Скопируй точный размер в байтах и имя файла без каталогов; один файл — один стабильный `idempotency_key` (например, UUID). Запрос пользователя «добавь эти фото» разрешает загрузку черновиков в выбранную библиотеку, но сам по себе не включает отправку.
2. Вызови `ermiy_request_avito_photo_upload` через `call_write_tool` с выбранной тройкой, `filename`, `bytes`, `idempotency_key`. Сохрани `media_id`. Если вернулся уже готовый объект без ссылки, проверь его статус; не создавай дубль.
3. В пределах `expires_at` (обычно 5 минут) отправь **сырой файл** по возвращённому `upload_url`: метод `PUT`, `Content-Type: application/octet-stream`, `Authorization: Bearer <upload_token>`. Не используй multipart, base64, строку локального пути или внешний URL вместо тела файла. Выполняй этот HTTP-запрос только к выданному LidFly адресу; не переноси токен при редиректе на другой адрес. Используй защищённую передачу секрета средствами среды, без вывода токена в консоль, историю команд, отчёт или переписку.
4. Прочитай `ermiy_get_avito_photo`. Успешная загрузка — `upload_state:"ready"`; `state:"draft"` при этом означает, что помощник ещё не может отправлять фото. Сервер подготавливает изображение для чата; исходный файл не становится публичной ссылкой.

После разрыва PUT или тайм-аута сначала прочитай статус, а не загружай заново. При `processing` подожди и перечитай с ограниченным числом проверок; если обработка не закончилась, сообщи незавершённый результат. При `awaiting` или `failed` ориентируйся на `failure_code`: для повторяемой технической ошибки запроси ту же загрузку с прежними `filename`, `bytes` и ключом, получи текущий токен и передавай **тот же файл**. Истёкшая незавершённая загрузка получает новый токен, старый перестаёт работать. При `file_deleted:true`, окончательном отказе или исчерпанной квоте не запускай бесконечные повторы; исправленный/заменённый файл требует новой загрузки и нового ключа.

## Описать и разрешить отправку

Помощник выбирает фото **по описанию**, а не распознаёт загруженные изображения. Укажи, что изображено и для какого запроса покупателя это подходит, например: «Шкаф модели А: задняя стенка и крепления; отправлять при просьбе показать вид сзади». Лимит описания — 300 символов. Если клиент может увидеть файл, используй видимое содержимое; если нет — возьми описание у владельца, не выдумывай его по имени файла.

- `scope_kind:"items"` + `item_ids` — только конкретные проверенные объявления. Нельзя угадывать ID по названию или переносить их из другого подключения.
- `scope_kind:"all"` + `item_ids:[]` — все объявления этого подключения в пределах его доступа, включая будущие. Выбирай только при явном намерении владельца использовать фото как общее.
- `sort_order` задаёт порядок; помощник отправляет до трёх подходящих фото за ответ, а не всю библиотеку. Уже отправленные фото не повторяются без просьбы покупателя.

Прочитай актуальную карточку, затем сохрани настройки через `ermiy_update_avito_photo` с её `expected_revision` и новым ключом изменения. Отсутствие `state` сохраняет прежний статус. Перед `state:"active"` должны быть готовы файл, непустое описание и область. Покажи владельцу фото/имена, описания и область; активируй только в пределах его явного разрешения отправлять эти фотографии покупателям. Уже данное однозначное разрешение не запрашивай повторно. Если заказана только загрузка, оставь `draft`.

Перечитай результат и проверь описание, область, порядок и `state`. Конфликт ревизии требует перечитать изменения UI и согласовать их с текущей задачей; не подставляй новую ревизию вслепую. При неизвестном результате `call_write_tool` сначала используй `get_write_operation_status`, затем карточку; не создавай другую операцию лишь из-за потерянного ответа.

`draft` выключает использование. `archived` убирает фото из выбора по явному запросу владельца, но не удаляет сообщения у покупателей. Байты неизменяемы: замена — новая загрузка, а судьбу старого фото определяет запрос владельца. Не архивируй другие файлы ради освобождения квоты без разрешения. Черновики очищаются через 24 часа без изменений, файлы архива — через 30 дней; учитывай серверный `file_deleted`.

## Проверить результат

В отчёте отдели загруженные черновики от фото, разрешённых для отправки, назови область и незавершённые файлы. Можно проверить подбор в тестовом диалоге UI с выбранным объявлением. Загрузка и настройка библиотеки сами не отправляют сообщений покупателям, не включают канал и не списывают платный ответ. Реальную отправку нельзя утверждать по `ready`/`active`; тест в UI также не отправляет ничего в Авито.
