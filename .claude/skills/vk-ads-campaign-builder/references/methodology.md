# VK Ads methodology

Start with get_provider_context(provider: "vk") when the VK cabinet/client is unknown; when the user named a campaign, call resolve_campaign_scope first. It searches Workspace campaigns before live VK scopes.
client_id selects the VK Ads client cabinet. For saved VK user IDs from the browser switcher, client_id is still passed from provider context, but runtime uses hidden _user_id instead of agency_client_credentials.
If the user names a VK user ID from the VK Ads switcher and it is not saved yet, ask them to add it in the LidFly cabinet first. Tools should normally use connection_id + client_id from provider context; vk_user_id is only a compatibility argument for saved manual user_filter cabinets.
Manual user_filter cabinets support reads plus a narrow write allowlist through _user_id: use vk_manage_ad_groups for status/max_price, vk_manage_campaigns for status/budget_limit/budget_limit_day/date_start/date_end/max_price, vk_manage_banners for banner status, and vk_update_lead_form for a lead-form name.
Do not use manual user_filter for ad group price, object creation, uploads, or single update tools vk_update_campaign/vk_update_ad_group/vk_update_banner. Explain that price and full edits require official agency/manager API access or a separate VK OAuth for the client.
For ad groups with autobidding_mode=max_goals, change the cap through max_price and reread the group. A live check showed price can return success while the value remains unchanged.
If several scopes are available and the user did not specify project/client/campaign, ask a short clarification instead of silently using default.
Then use vk_get_campaigns, vk_get_ad_groups, vk_get_banners, vk_get_statistics and directory tools as needed.
Use fields, limit and offset for every list call. Keep overview fields small, then fetch one entity in detail.
For campaign creation: choose objective, targetings and 2-5 creative variants. Call vk_get_packages with objective plus available_only=true and use only package_request=allowed; status=active alone does not mean the package is available to this cabinet.
Build the campaign with exactly one blocked bootstrap ad_group and no nested banners, then call the read-only vk_prepare_campaign with the full payload. Read checked_packages.goal_mode: required needs a valid named goal, forbidden must not receive one, unsupported blocks the write. priced_event_type=41 for VK community joins and priced_event_type=51 for lead forms are package-defined and forbidden must not receive priced_goal. A lead-form id is not PricedGoal.source_id. Never infer policy from objective, package name, or options.settings.priced_goal.
Do not remove an incompatible priced_goal automatically. Agree with the user whether to keep CPC/CPM without a named goal or select a compatible goal/oCPM package. Fix ready=false before asking for confirmation. After confirmation pass normalized_arguments to vk_create_campaign; it rechecks package access immediately before POST and creates both objects blocked.
Create remaining groups and banners with their separate write tools. For priced_event_type=51, read the form with vk_get_lead_forms and attach it only to banner content.lead_form_id plus the VK-internal https://vk.com/leadads/form/<id> URL. Reread every object before a separate final activation action.
vk_create_campaign returns operation_id/outcome/retry_safe/message_ru/next_action. For unknown or ambiguous call the top-level read-only get_write_operation_status(operation_id) immediately. It performs GET reconciliation only. Do not rename or retry create. If it returns next_write, run that action only through call_write_tool after explicit user confirmation; otherwise offer the safe support draft from support_hint.
If vk_prepare_campaign returns package_priced_goal_forbidden/package_priced_goal_required/package_goal_policy_unsupported, stop before POST and follow goal_mode. If VK returns inconsistent_priced_goal, treat provider_goal_package_mismatch as non-retryable for the same payload.
If vk_prepare_campaign or VK returns package_unavailable/invalid_package, do not retry with the same or a guessed package_id. Reread vk_get_packages(objective=..., available_only=true), offer an allowed package, or explain that access must be requested in VK Ads.
Use exactly one budget type at each level: budget_limit or budget_limit_day. With autobidding and budget_limit, date_end is required. Campaign creation includes exactly one bootstrap ad_group; do not create an empty campaign first.
For agency or manager accounts, pass client_id when acting on a client account.
For campaign writes, pass workspace_project_id and scope_arguments from resolve_campaign_scope. call_write_tool has a safety preflight for campaign id targets, but ambiguous Workspace/provider matches are blocked until you specify workspace_project_id.
