# Yandex Direct / Metrika / Webmaster methodology

Start with get_provider_context(provider: "yandex", query: "project search", client_login: "exact-login") when the account/client/project is unknown. query is free project/account search; client_login is the exact Direct login and is checked independently against the live directory. Legacy clients may still put a syntactically valid login in query, but it never becomes executable without an exact live match. When the user named a campaign, call resolve_campaign_scope first; it searches Workspace campaigns before live provider scopes.
connection_id selects the Yandex OAuth connection; client_login selects the Direct client cabinet inside that connection. Pass tool_args from provider context; do not invent client_login from an account or project name.
For site/indexing/Sitemap/recrawl/ИКС/search-query tasks use webmaster_* tools. Yandex Webmaster is a separate OAuth app, not Direct/Metrika; do not pass client_login.
Webmaster workflow: search_tools(provider: "yandex", query: "вебмастер сайт индексация") -> get_tool_schema -> webmaster_get_hosts -> use exact host_id in host-specific tools.
For Webmaster writes such as add/delete host, verification, Sitemap add/delete, recrawl, feeds and Pro export, use call_write_tool only after explicit user intent.
Yandex Direct landing content on clients.site and Turbo pages is UI-only: the public API cannot read its block settings or create, edit, publish or delete that content. A matching search_tools request adds capability_notice.status=unsupported_by_provider_api to the ranked tools. Apply it only to the unsupported part, explain its user_action, and do not substitute ad/campaign writes or escalate to LidFly support. get_turbo_pages reads published Turbo-page metadata and related turbo.site URLs, not a clients.site catalog; get_leads reads submitted form data only.
If several scopes are available and the user did not specify project/client/campaign, ask a short clarification instead of silently using default.
Then use discovery: search_tools(query: "кампании", provider: "yandex") and get_tool_schema before the first domain tool call.
Read current state before writes: campaigns, ad groups, ads, keywords, bids, strategies, goals and relevant Metrika reports.
For large reads pass compact field_names plus limit/offset. v3 applies compact defaults, but explicit fields are still better.
For a user-requested export to their connected Google Drive, standard report fields (aggregated metrics, entity ids, ad copy and public creative URLs) may be passed to that document action; never include auth secrets. Call the real connector and report its actual error instead of inventing a privacy block. In Google Sheets write the locale-neutral single-argument =IMAGE("URL") with the original public URL; drive.google.com URLs are unsupported by IMAGE. If readback shows #REF! or an external-data access prompt, leave the IMAGE formula in place, ask an editor to open the sheet in a desktop browser and click Allow access once, then reread after confirmation. Never replace the IMAGE formula with HYPERLINK, plain text, or a Drive-file link.
Do not use Master Campaigns / Simple Start as a setup strategy. Search campaigns are preferred by default; networks require explicit user intent.
For agency or representative access, pass client_login only when provider context returns scope_type=client/tool_args.client_login. For primary/ordinary scopes pass connection_id only.
Never derive client_login from external_entity_key or Direct ClientId. If tool_args has no client_login, omit it.
Respect scope_issues: automatically execute only a read-only next_action with may_execute_automatically=true. Never guess around manual_scope_review, ambiguity, conflict, directory outage, or login-not-found.
If a selected Workspace has no Direct link, get_provider_context may return provider_link_candidates. They are verified personal scopes but not executable in the project yet. Choose the exact candidate and use only its prepared next_action through call_write_tool after user intent/confirmation; never invent client_login or escalate a missing link to support.
For campaign writes, pass workspace_project_id and scope_arguments from resolve_campaign_scope. call_write_tool has a safety preflight for campaign_id/ids, but if it cannot infer one Workspace/provider scope it will ask you to resolve first.
