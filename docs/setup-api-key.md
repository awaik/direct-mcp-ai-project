# Подключение LidFly через API-ключ

OAuth остаётся рекомендуемым способом. Подключение через API-ключ подходит, если вы предпочитаете управлять ключом самостоятельно или ваш клиент не поддерживает OAuth.

Для обоих способов используется `https://lidfly.ru/mcp/v3`. При подключении через ключ клиент отправляет `Authorization: Bearer …`. Сам ключ хранится локально в переменной окружения `LIDFLY_TOKEN`; в MCP-конфиге остаётся только ссылка на неё. Для OAuth переменная не нужна.

## 1. Подготовьте ключ

Используйте API-ключ из личного кабинета LidFly. Не копируйте OAuth-токены из хранилища клиента и не отправляйте секрет в чат.

### macOS и Linux: bash или zsh

Из папки проекта создайте локальный файл, если его ещё нет:

```bash
if [ ! -e tokens.env ]; then
  cp tokens.env.example tokens.env
fi
chmod 600 tokens.env
```

Откройте `tokens.env` в редакторе и заполните `LIDFLY_TOKEN`. Существующие переменные в файле сохраните. `tokens.env` уже исключён из Git; файл `tokens.env.example` должен оставаться без секретов.

Перед запуском клиента загрузите переменную в текущий терминал:

```bash
set -a
source ./tokens.env
set +a
test -n "${LIDFLY_TOKEN:-}" && echo 'LIDFLY_TOKEN задан'
```

Последняя команда проверяет наличие значения, не выводя его. После настройки конфига запустите `claude`, `codex`, `opencode` или `code .` из этого же терминала. В новом терминале загрузите файл снова. Сами клиенты не обязаны автоматически читать `tokens.env`.

### Windows: PowerShell

Задайте ключ для текущей сессии через скрытый ввод:

```powershell
$lidflyKey = Read-Host 'API-ключ LidFly' -AsSecureString
$env:LIDFLY_TOKEN = [System.Net.NetworkCredential]::new('', $lidflyKey).Password
$lidflyKey.Dispose()
```

После настройки конфига запустите клиент из этого же PowerShell. Значение действует для текущей сессии и запущенных из неё процессов; в новой сессии его нужно задать заново.

Приложение, открытое через Dock, меню «Пуск» или уже работающий процесс VS Code, может не получить переменную из терминала. Для CLI используйте запуск из подготовленного терминала. Для приложения или расширения задайте переменную в окружении запускающего его процесса и полностью перезапустите приложение; ввод `export` во встроенном терминале уже открытого приложения не меняет его окружение.

## 2. Выберите пример для клиента

Измените только подключение `lidfly` в своём локальном конфиге, сохранив остальные серверы и настройки. Примеры находятся в разделе «Подключение через API-ключ» соответствующей инструкции:

| Клиент | Инструкция | Как читается ключ |
|---|---|---|
| Claude Code | [setup-claude-code.md](setup-claude-code.md) | `Bearer ${LIDFLY_TOKEN}` |
| Codex | [setup-codex.md](setup-codex.md) | `bearer_token_env_var = "LIDFLY_TOKEN"` |
| VS Code / Copilot | [setup-vscode-copilot.md](setup-vscode-copilot.md) | `Bearer ${env:LIDFLY_TOKEN}` |
| OpenCode | [setup-opencode.md](setup-opencode.md) | `Bearer {env:LIDFLY_TOKEN}`, `oauth: false` |

Для этих клиентов сохраняется native HTTP/remote MCP; устанавливать `mcp-remote` не нужно. Если клиент уже подключён через OAuth-плагин или другой конфиг, оставьте активным одно выбранное подключение LidFly.

Наличие переменной само по себе не включает авторизацию через ключ. Нужна настройка из инструкции клиента. Готовые конфиги репозитория продолжают использовать OAuth.

## 3. Проверьте подключение

В новом чате попросите:

```text
Покажи мои доступные Пространства и рекламные кабинеты.
```

При ошибке авторизации проверьте, что ключ актуален, переменная непустая и доступна именно процессу клиента. Не подставляйте настоящий ключ в версионируемый конфиг для диагностики.

Для возврата к OAuth удалите добавленную настройку Bearer из подключения; в OpenCode также удалите `oauth: false`. Перезапустите клиент и выполните OAuth-вход по его инструкции. Простого удаления переменной окружения недостаточно.
