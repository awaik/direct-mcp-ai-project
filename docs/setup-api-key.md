# Подключение LidFly MCP через API-ключ (`LIDFLY_TOKEN`)

Авторизация через браузер по email (**OAuth**) — рекомендуемый способ по умолчанию для работы с **Яндекс Директом, Метрикой, Вордстатом, Вебмастером, VK Рекламой, ВКонтакте, Telegram, мессенджером MAX, Авито и сайтами LidFly**.

Подключение через статический **API-ключ** подходит в двух случаях:
- вы предпочитаете управлять ключом самостоятельно через переменные окружения;
- ваш ИИ-клиент или CI/CD-окружение не поддерживает интерактивный браузерный OAuth.

Для обоих способов используется один и тот же сервер: `https://lidfly.ru/mcp/v3`. При подключении через ключ клиент передаёт заголовок `Authorization: Bearer …`. Сам секрет хранится только локально в переменной окружения `LIDFLY_TOKEN`, а в конфигурационном файле MCP указывается безопасная ссылка на эту переменную.

---

## 1. Подготовьте API-ключ

Скопируйте API-ключ в личном кабинете **[lidfly.ru/app](https://lidfly.ru/app)** (**Настройки → API-ключ → «Скопировать ключ»**). Не копируйте временные OAuth-токены из хранилища клиента и никогда не вставляйте ключ в текст чата с нейросетью.

### macOS и Linux (`bash` или `zsh`)

В папке проекта создайте локальный файл `tokens.env` из шаблона, если его ещё нет:

```bash
if [ ! -e tokens.env ]; then
  cp tokens.env.example tokens.env
fi
chmod 600 tokens.env
```

Откройте `tokens.env` в редакторе и впишите свой ключ в переменную `LIDFLY_TOKEN`. Файл `tokens.env` уже добавлен в `.gitignore` и не попадёт в Git; файл `tokens.env.example` должен оставаться пустым шаблоном.

Перед запуском ИИ-клиента загрузите переменную в текущую сессию терминала:

```bash
set -a
source ./tokens.env
set +a
test -n "${LIDFLY_TOKEN:-}" && echo 'LIDFLY_TOKEN задан'
```

Последняя команда проверяет, что переменная не пустая, не выводя сам секрет на экран. После этого запустите `claude`, `codex`, `opencode` или `code .` **из этого же окна терминала** (сами клиенты не обязаны автоматически читать файл `tokens.env`).

### Windows (`PowerShell`)

Задайте ключ для текущей сессии PowerShell через защищённый ввод:

```powershell
$lidflyKey = Read-Host 'API-ключ LidFly' -AsSecureString
$env:LIDFLY_TOKEN = [System.Net.NetworkCredential]::new('', $lidflyKey).Password
$lidflyKey.Dispose()
```

После настройки конфига запустите свой ИИ-клиент из этого же окна PowerShell.

> **Важно для графических приложений (VS Code, Cursor):** приложение, запущенное через иконку в Dock, меню «Пуск» или уже открытое окно, не увидит переменную из нового терминала. Полностью закройте редактор и запустите его командой `code .` из того терминала, где задан `LIDFLY_TOKEN`.

---

## 2. Настройте конфиг своего ИИ-клиента

Измените только блок `lidfly` в локальном конфиге вашего клиента, сохранив остальные серверы:

| ИИ-клиент | Пошаговая инструкция | Как подставляется переменная |
|---|---|---|
| **Claude Code** | [setup-claude-code.md](setup-claude-code.md#подключение-через-api-ключ) | `Bearer ${LIDFLY_TOKEN}` |
| **OpenAI Codex** | [setup-codex.md](setup-codex.md#подключение-через-api-ключ) | `bearer_token_env_var = "LIDFLY_TOKEN"` |
| **VS Code / GitHub Copilot** | [setup-vscode-copilot.md](setup-vscode-copilot.md#подключение-через-api-ключ) | `Bearer ${env:LIDFLY_TOKEN}` |
| **OpenCode** | [setup-opencode.md](setup-opencode.md#подключение-через-api-ключ) | `Bearer {env:LIDFLY_TOKEN}`, `oauth: false` |

Для всех перечисленных клиентов используется прямой Streamable HTTP (`https://lidfly.ru/mcp/v3`) — устанавливать `mcp-remote` не нужно. Не смешивайте OAuth и статический `Authorization` в одном подключении.

---

## 3. Проверьте подключение

В новом чате отправьте проверочный запрос:

```text
Покажи мои доступные Пространства, рекламные кабинеты и подключённые площадки.
```

Если возникла ошибка авторизации, убедитесь, что ключ актуален в кабинете LidFly, а переменная `LIDFLY_TOKEN` доступна процессу вашего ИИ-клиента.

Для возврата к браузерному OAuth удалите добавленную настройку `Authorization` / `bearer_token_env_var` из конфига (в OpenCode также удалите `oauth: false`), перезапустите клиент и войдите по email.
