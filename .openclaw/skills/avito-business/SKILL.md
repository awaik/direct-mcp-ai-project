# Авито

Используй для профилей Авито и прикреплённых клиентов Avito Promo: объявления, статистика, чаты, отзывы, заказы, остатки, продвижение, доставка, работа, недвижимость, Автотека и партнёрские API.

Не используй этот skill для рекламных кампаний, групп, креативов и рекламного `account_id`: для них нужен `$avito-ads`.

## Scope

1. Если профиль не определён, вызови напрямую `get_provider_context({ provider: "avito", query? })`.
2. Копируй только точные значения из возвращённых `tool_args`.
3. `avito_user_id` — ID обычного профиля Авито. Не подменяй его 9-значным рекламным `account_id`.
4. `resolve_campaign_scope` для `provider="avito"` не используется: кампании принадлежат отдельному провайдеру `avito_ads`.
5. Если выбран проект Пространства, передавай точный `workspace_project_id`; при неоднозначности остановись и уточни его.
6. Для `scope_type=agency_client` используй только `connection_id` и `agency_client_id` из `tool_args`. Подписка Avito Promo — диагностика агентства, а не разрешение на другие операции.

## Capability-first workflow

1. `search_tools({ provider: "avito", query })`.
2. Если результатов нет, повтори `search_tools({ provider: "avito" })`.
3. Получи схему через `get_tool_schema({ tool_name })`.
4. Если инструмент вернулся с `unavailableReason`, объясни причину. Не угадывай другое имя и не смешивай OAuth/personal credentials разных профилей.
5. Read-only действие выполни через `call_tool`.
6. Любое изменение — только через `call_write_tool`.

Наличие подключения не означает доступ ко всем 25 разделам API. OAuth scopes и партнёрские capabilities выдаются Авито отдельно; отказ одного раздела не блокирует остальные.

## Аудит профиля

Аудит — только чтение. Независимые чтения делай одним шагом.

1. Профиль, деньги, репутация: `avito_user_get_accounts_self`, `avito_user_get_accounts_balance`, `avito_ratings_get_info`.
2. Все объявления: `avito_item_get_items` с `query.per_page` (меньше 100) и `query.page`. Общего числа ответ не содержит: если строк ровно `per_page`, прочитай следующую страницу. Другие статусы — через `query.status`.
3. Статистика всех прочитанных объявлений: `avito_item_post_v1_stats_accounts_items` — до 200 `itemIds`, глубина до 270 дней, поля `uniqViews`, `uniqContacts`, `uniqFavorites` (`views`, `contacts`, `favorites` Авито пометил устаревшими). Сводка профиля по дням или объявлениям — `avito_item_post_v2_stats_accounts_items`.
4. Расходы — `avito_item_post_stats_accounts_spendings`, звонки — `avito_item_post_accounts_calls_stats`, подключённые услуги — `avito_promotion_post_items_services_get`.
5. Карточка (`avito_item_get_accounts_items_by_item_id`) проверяет статус, даты и услуги. Описания, фото и видео в ней нет; перед анализом содержания получи сам текст или изображения от пользователя либо из доступного источника.

`avito_item_post_v2_stats_accounts_items` и `avito_item_post_stats_accounts_spendings` выполняются не чаще раза в минуту на профиль: заранее выбери период, группировку и показатели; после отказа по лимиту не повторяй вызов сразу.

| Вывод | Необходимое основание |
| --- | --- |
| Охват аудита | В ответе — сколько объявлений прочитано и по скольким есть статистика. Обрезанный результат или непрочитанные страницы называй прямо. |
| Мало просмотров или контактов | Сравнение с другими объявлениями профиля за тот же период с учётом даты публикации и сезона: для сезонного товара — `wordstat_dynamics` по главной фразе и региону. Без этого — гипотеза. |
| Цифры за период | Точные даты запроса. При `periodGrouping` `week`/`month` дата строки — первый день недели или месяца, даже если период начался позже; уникальные пользователи считаются только в пределах дня. |
| Сменить категорию | Подтверждённое правило Авито для этой категории и товара. Без него — вопрос к проверке в кабинете, а не рекомендация. |
| Фото, видео, описание | Фактически полученный текст, изображения или актуальная запись фида с проверенным соответствием ID. Карточка статуса этого не подтверждает. |
| Окупаемость продвижения | Расходы и контакты или звонки за один и тот же период. |

Источники: [Item API Авито](https://developers.avito.ru/api-catalog/item/documentation) (`GET /core/v1/items`, `POST /stats/v1/accounts/{user_id}/items`), лимиты частоты — манифест LidFly по документации Авито; сверено 15.10.2026.

## Диагностика спада и материалы объявления

Проверяй статус и даты → сопоставимую динамику → доступные настройки оплаты и продвижения → сравнение с похожими объявлениями. Это порядок рассуждения, а не обязательный набор запросов при любом вопросе. Для конверсии совпадают объект, период, определение метрики и уникальность; несопоставимые звонки и просмотры номера не дели друг на друга. Для количества обращений достаточно contactsMessenger: список переписок нужен для анализа общения, а не для воронки.

Если расходы показывают CPA, различай кошелёк и текущий CPA-баланс: `avito_cpa_post_balance_info`. При необходимости прочитай ставки через доступное CPA/CPX-чтение. balance v3 — копейки, не отдельный advance/debt. Отрицательный баланс сам по себе не доказывает скрытие объявления; связь расходов и контактов при CPA тоже не доказывает причину спада. Не требуй пополнения без основания. Если чтение или ставка недоступны, назови конкретную непроверенную часть и следующий шаг из отказа, сохрани полезные выводы по доступным данным. Сохраняй условность шага: «если персональные ключи не настроены» не означает, что они точно отсутствуют или гарантированно устранят 403. Наличие денег в кошельке не подтверждает возможность перевода на CPA-баланс; способ пополнения проверяй отдельно, не придумывай его.

После отказа или заглушки конкретной веб-страницы объясни ограничение и попроси текст, изображения или нужный материал. Не считай весь avito.ru постоянно недоступным. autoload_item_id помогает найти запись, но не доказывает доступность фида или совпадение с текущей публикацией: проверяй ID и актуальность. Без материалов допустимы общие гипотезы, а не вывод о недостатках конкретного текста/фото.

Для финального текста отделяй слова клиента и проверенные материалы от собственных предложений. «Согласен» не подтверждает все ранее предложенные обещания. Неизвестные технологии, гарантии, материалы, оплата, график и сроки ответа опусти либо оставь [укажите …]; спроси только то, что нужно для текста.

Можно предложить сохранить подтверждённые сведения в точно выбранный проект; создавать проект для подготовки текста не требуется.

Источник состава карточки и единиц: локальные официальные OpenAPI [item](https://www.avito.ru/developers/api-catalog/item/documentation) и [cpa](https://www.avito.ru/developers/api-catalog/cpa/documentation), сверено 19.10.2026. Правило блокировки показов по balance v3 не установлено.

## Подбор BBIP

Сначала варианты и прогноз по точным ID. Единицы и расчёт бери из серверных пометок: price — копейки за день, totalPrice прогноза — уже за период. Учитывай ошибки каждого объявления и не выдавай частичный прогноз за полный. Перед заказом покажи дневную цену, длительность, итог и справочное назначение oldPrice из preflight. Старые расчёты в сводке беседы не являются источником цены; при расхождении используй актуальные варианты/прогноз. Создание заявки не подтверждает подключение услуги.

## Messenger API

Доступ к Messenger API входит в подписку Авито, а не подключается в LidFly: для «Товаров» и «Работы» нужен уровень «Максимальный», для «Услуг» — «Расширенный» или «Максимальный». Если вместо текста сообщений Авито возвращает тарифную заглушку, направь пользователя в Авито Pro → «Тариф»/«Подписка» проверить этот уровень или уточнить доступ у поддержки Авито.

## Write guardrails

Каждый write:

1. Читает текущее состояние.
2. Проверяет входные данные, профиль, capability, цену/баланс и последствия.
3. Показывает план и получает явное подтверждение: во встроенном чате — следующий текст пользователя или серверное действие для того же sealed ChangeSet; во внешнем MCP — текстовое согласие в действующем workflow клиента.
4. Выполняет ровно один `call_write_tool`.
5. Перечитывает объект и показывает before/after.

Деньги, продвижение, доступы, заказы, статусы, blacklist, рассылки и юридические операции считай destructive. Перед платной операцией покажи профиль, объекты, услугу, цену, баланс и ожидаемое списание.

Writes не повторяются автоматически. При `outcome=unknown` или `ambiguous` вызови напрямую `get_write_operation_status({ operation_id })`. Если надёжного readback нет, сообщи, что результат требует ручной проверки в Авито.

## Autoload updates

`POST /autoload/v1/upload` не редактирует одно объявление: он запускает обработку полного фида по URL из профиля и может опубликовать или активировать все подходящие записи. Считай его destructive.

Для безопасного обновления описания, телефона, часов работы или других полей:

1. Прочитай `GET /autoload/v2/profile` и `GET /autoload/v4/uploads/current` либо `/last_successful`.
2. Объясни, что полную запись меняют в источнике фида; отдельного универсального edit endpoint у Avito API нет. URL и расписание самого фида меняются через `POST /autoload/v2/profile`.
3. Требуй сохранить тот же неизменный `Id`: по нему Авито распознаёт объявление между загрузками. Покажи URL фида и охват изменений, затем получи явное подтверждение полного запуска.
4. Вызови upload один раз. После обработки проверь `Id → Avito ID` через `GET /autoload/v2/items/avito_ids` и результат через `/autoload/v4/uploads/current/items` либо `/last_successful/items`.

Не обещай сохранение Avito ID или накопленной статистики как безусловную гарантию провайдера. Подтверди результат чтением; новый или изменённый `Id` может быть распознан как другое объявление.

## Private data

- PII, резюме, записи звонков, коды доставки и приватные файлы требуют project access `admin`.
- Не показывай OAuth/access/refresh tokens, Client Secret, provider payload или внутренний routing.
- Голосовые сообщения, записи звонков и PDF-этикетки возвращаются только временной подписанной ссылкой. Не сохраняй и не экспортируй её.
- Не настраивай автоматические AI-ответы на сообщения.

## Scheduled tasks

В первом релизе автозапуски для `avito` разрешают только read tools. Для любого будущего изменения создай ручную задачу через `workspace_add_tasks`, чтобы пользователь подтвердил действие в новом сеансе.
