# Creative page direction for LidFly

Use before creating a page or substantially changing its appearance. For a small
correction, preserve the existing direction and inspect only the affected area.

## Establish the brief

Read the site's current pages, active design template, theme, inherited chrome,
fonts and available assets. Identify the audience, page purpose, main message,
desired action and content that must remain. Infer routine choices; ask only
when a missing fact changes the result. Do not invent reviews, prices or results.

Determine whether this is a new composition, a refinement or a faithful transfer.
For a reference, inspect the whole page and its mobile view, not just the hero.
Describe useful principles (hierarchy, grid, density, image treatment); copying
the reference's brand, content or artwork requires the corresponding brief.
A 1:1 migration follows lidfly-page-migration and preserves all source sections.

## Choose one buildable direction

State a short concrete direction: mood, palette, type pairing with the required
language coverage, grid, spacing rhythm and image treatment. Keep existing brand
rules. A restrained documentation page can be the right design; novelty and
decorative effects are not acceptance criteria.

For example, a training program can use compact editorial headings, readable
exercise instructions, small consistent illustrations and clearly separated
workout tabs. Seven exercises do not need seven full-screen promotional panels.
A personal trainer's sales page may instead need a strong portrait and a clear
offer. Decide from the visitor's task.

Outline each section's purpose, content, dominant visual, target interaction and
mobile treatment. Give the page a clear opening and a logical next action.
Use as many sections as the content needs: the blueprint's suggested count is
not a quota. Do not pad a directory, article or knowledge page with pricing/FAQ.

## Map the direction to the platform

Discover real templates with lidfly_list_site_design_templates and inspect an
existing template with lidfly_audit_site_design_template. Match the site's task
to an available template; do not invent template IDs or replace an active one
merely for a single page. Use lidfly_recommend_page_blueprint as a starting point,
then verify selected blocks and their supported interactions.

Record a compact implementation brief: route → section → block → key props →
asset/crop → mobile arrangement. Specify type hierarchy, line lengths, content
width, contrast and spacing using theme tokens and supported block options.
Read frontend-page-craft.md before building and visual-assets.md when media is
needed. Carry the direction into implementation within the authorized scope.
Judge the rendered result with visual-qa.md.
